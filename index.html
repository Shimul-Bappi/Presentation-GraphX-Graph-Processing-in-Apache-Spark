Section 1.1

Big Data and Graph Data

A lot of today's data is not a plain list — it is a web of connected things.

  • Big Data comes from social apps, online shops, transport systems, science labs, and message systems.
  • Much of it is connected data — things joined to other things.
  • A graph has two parts: vertices (the things) and edges (the links between them).
  • In a social app, each person is a vertex and each friendship is an edge.
  • Here the connections matter as much as the things — that is the big difference from normal tables.
Where graph data comes from
Section 1.2

Why Do We Need Graph Processing?

Normal tools look at rows one by one. Graph tools look at how rows are joined.

📊 Table Data

Rows and columns

  • Each row lives alone and knows nothing about other rows.
  • Good for sales records, sensor readings, and simple logs.
  • Hard to answer: “Who are the friends of my friends?”
🕸️ Graph Data

Nodes and links

  • Every node knows its neighbors directly.
  • Good for finding groups, paths, and important people.
  • Easy to answer: “Find the shortest road from A to B.”
🖥️ One Computer Is Not Enough

Big networks have billions of people and links. One machine cannot hold or process all of that.

⚡ Split the Work

GraphX divides the graph across many machines so all the parts are worked on at the same time.

Section 2.1

What Is GraphX?

Spark's built-in part for graphs and graph-style computing.

  • GraphX is the graph part of Apache Spark. It comes with Spark — no extra install.
  • It adds a graph model on top of Spark's normal data engine.
  • The model is a directed multigraph: arrows go one way, and two nodes can have more than one arrow between them.
  • It gives you four things: graph operators, graph algorithms, graph builders, and the Pregel engine.
GraphX sits inside Spark
Sections 2.2 & 2.3

GraphX and Apache Spark

How the two fit together, and what “graph-parallel” really means.

Runs Inside Spark

Uses the same workers and memory Spark already manages. You can mix normal data work and graph work in one program.

Safe and Self-Healing

Graphs cannot be edited in place. A new graph is made and unchanged parts are reused. If a machine dies, Spark rebuilds the lost piece.

Graph-Parallel Work

Instead of treating each record alone, a node can use information from its neighbors to update itself.

Section 4.1

The Property Graph

The most important idea in GraphX — a graph where everything can carry extra information.

  • A property graph is a directed multigraph where user data is attached to every node and every link.
  • Directed = the arrow points one way.
  • Multigraph = two nodes can have several links. Two people can be friends and co-workers.
  • Each node has a unique 64-bit ID called a VertexId.
  • Two type slots: VD = vertex data, ED = edge data.
Two people, two different links
Graph = Vertices + Edges + Vertex Properties + Edge Properties

Sections 4.5 – 4.7

VertexRDD, EdgeRDD, and EdgeTriplet

How GraphX actually stores and views your graph inside.

Node Storage
VertexRDD
  • Holds node ID + node data.
  • Each ID appears only once.
  • A hidden index makes joins much faster.
VertexRDD = ID + Attribute
Link Storage
EdgeRDD
  • Holds every link in the graph.
  • Organised by the partition plan.
  • Data and shape stored separately for speed.
EdgeRDD = Src + Dst + Attribute
Combined View
EdgeTriplet
  • Joins source + link + target into one packet.
  • Shows both ends plus the relationship.
  • Essential for Pregel message passing.
Src + Edge + Dst Attributes

Sections 5.1 – 5.3

Graph Operators

Change properties, reshape the graph, or pull in outside data.

🎨 Property Operators

Change data, keep the shape

  • mapVertices — change every node's data.
  • mapEdges — change every link's data.
  • mapTriplets — change link data using both ends.
  • Shape stays the same → index reused → fast.
✂️ Structural Operators

Reshape the graph itself

  • subgraph — keep only parts that pass a test.
  • reverse — flip all arrows.
  • mask — keep only parts in another graph too.
  • groupEdges — merge duplicate links.
🤝 Join Operators

Bring in outside facts

  • joinVertices — match outside data by node ID.
  • outerJoinVertices — keeps unmatched nodes too.
Graph + External Data → Richer Graph
Section 5.4

Neighborhood Aggregation

Collect information from the nodes sitting next to you.

📬 How aggregateMessages Works
  1. Look at each edge triplet in the graph.
  2. Send a message along that link.
  3. Combine all messages arriving at the same node.
  4. Use the combined value to update that node.

Example: “Add up the ages of all my friends.” Sending small messages is far cheaper than copying whole neighbor lists.

Three neighbors send notes to node X
Edge Triplets → Send Messages → Combine at Node → Update Node
Section 6

The Pregel API — Round by Round

Like people passing notes in a classroom, one round at a time.

🔄 One Round (a “Superstep”)
  1. Nodes receive messages from the last round.
  2. Each node updates its own value.
  3. New messages are created.
  4. Messages go to neighbors only.
  5. Repeat until no messages remain or the round limit is reached.

Because notes travel only between neighbors, GraphX can plan the work very efficiently.

🗺️ Example: Shortest Path (SSSP)
  • Pick a start node. It gets distance 0.
  • All other nodes start at infinity.
  • Each round, nodes tell neighbors how far away they are.
  • A node updates only if it hears a shorter distance.
  • When nobody finds a shorter path, the job is finished.
Sections 7.1 & 7.2

PageRank and Connected Components

Two of the most-used ready-made algorithms in GraphX.

⭐ PageRank

Who is the most important?

  • A node becomes important when other important nodes point to it.
  • Static — runs a fixed number of rounds.
  • Dynamic — runs until the scores settle within a tolerance.
  • Used for: web ranking, influencers, recommendations, citation networks.
🏘️ Connected Components

Which groups are separate islands?

  • Finds groups where everyone can reach each other.
  • Each group is labelled with its lowest node ID.
  • Example: A—B—C is one group, D—E is another.
  • Used for: friend clusters, network splitting, isolated systems.
Sections 7.3 & 7.4

Triangle Counting and Strongly Connected Components

Two more built-in algorithms for studying network shape.

🔺 Triangle Counting

How tightly knit is the group?

  • A triangle is three nodes all connected to each other.
  • More triangles = a tighter, more trusting community.
  • Edges must be in canonical order (smaller ID first) and the graph properly partitioned.
  • Used for: community detection, spam checking, local clustering.
🔁 Strongly Connected Components

Who can reach everyone and get back?

  • A group in a directed graph where every node can reach every other node.
  • Finds loops and cycles in one-way networks.
  • Example: A → B → C → A.
  • Used for: web links, dependency analysis, supply chains, telecom routing.
Section 8

Graph Builders and Vertex-Cut Partitioning

How graphs are created, and how they are split across machines.

🔨 Ways to Build a Graph
  • From a vertex RDD and an edge RDD.
  • From an edge list file — the loader auto-creates any missing nodes.
  • From edges only, when there is no separate node data.
  • From graph generators for testing.
✂️ Vertex-Cut Partitioning
  • Problem: one very popular node with millions of links overloads a single machine.
  • Solution: spread edges evenly and let the busy vertex sit on several machines as lightweight mirrors.
  • Cuts down network traffic and storage waste.
  • Pick the partition strategy that fits your graph.
No single machine gets overloaded
Section 9

Where GraphX Is Used

Anywhere the relationships between things carry real meaning.

👥 Social Networks

Users are nodes, friendships are links. Find influencers, spot communities, count triangles, rank users.

🛒 Recommendations

Customers and products are nodes; buying and viewing are links. Suggests the right item to the right person.

🌐 Web Analysis

Webpages are nodes and hyperlinks are directed edges. PageRank measures how important each page is.

🚌 Transport Networks

Cities and stations are nodes; roads, rails, and routes are links. Good for connectivity and path questions.

📚 Academic Networks

Researchers and papers are nodes; citations and joint work are links. Shows collaboration patterns.

📡 Communication

Devices and users are nodes; calls and data links are edges. Reveals network shape and connected groups.

Section 10

Advantages and Limitations

An honest look at what GraphX does well and where it struggles.

👍 Advantages
  • Distributed processing — big graphs run across many machines.
  • Built into Spark — no separate graph database needed.
  • Property graph model — nodes and links both carry real data.
  • Ready-made algorithms — PageRank, components, triangles.
  • Flexible operators — property, structural, join, aggregation.
  • Fault tolerance — lost partitions are rebuilt automatically.
  • Efficient storage — vertex-cut for very large graphs.
⚠️ Limitations
  • Harder to design — graph algorithms are trickier than plain data jobs.
  • Memory hungry — structures, partitions, and mid-results all need space.
  • Network traffic — machines talk a lot across partitions.
  • Many iterations — repeated rounds cost time and resources.
  • Partitioning matters — a poor split slows everything down.
  • Learning curve — VertexRDD, triplets, and Pregel take time to learn.
